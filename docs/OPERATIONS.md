# قائمة التشغيل قبل البيع

## ما تم التحقق منه آليًا

- نشر Vercel الإنتاجي يصل إلى `READY`.
- الصفحة الرئيسية والأصول الأمامية تستجيب بنجاح.
- صفحة الأرباح مشمولة في حزمة Vercel.
- ملفات المستودع وملفات الترحيل ومجلد الخلفية غير متاحة عبر HTTP.
- مسارات API القديمة معطلة.
- اختبارات HTTP وصياغة JavaScript تعمل في CI.
- جميع جداول `public` مفعّل عليها RLS.
- لا توجد دوال عامة قابلة للتنفيذ بدور `anon`.
- دوال `SECURITY DEFINER` في مخططي `public/private` محددة بـ `search_path`.
- تمت إضافة قيود على مبالغ استرداد مرتجعات البيع والشراء، ومعالجة تكلفة المخزون غير المعروفة، ومنع مسار الإلغاء القديم من تجاوز الاسترداد.

## شروط ما قبل فتح التسجيل التجاري على نطاق واسع

1. **حماية كلمات المرور المسرّبة:** فحص Supabase ما زال يبلغ أن هذه الحماية غير مفعلة. فعّلها من إعدادات Auth قبل الإطلاق العام.
2. **تسليم البريد:** لا توجد أدلة كافية من السجلات وحدها لتأكيد تسليم دعوات الأعضاء ورسائل التحقق وإعادة تعيين كلمة المرور. اختبر هذه الرسائل باستخدام SMTP إنتاجي.
3. **اختبار قبول كامل:** نفّذ دورة بيع وشراء ومرتجع وإلغاء ومدفوعات في مؤسسة اختبار منفصلة، وتحقق من المخزون والتقارير وكشوف الحسابات بعد كل خطوة. لم تُنشأ حركات اختبار جديدة في بيانات الإنتاج.
4. **استعادة قاعدة البيانات:** سجل Supabase يحتوي 53 إصدار ترحيل، بينما المستودع يحتوي 35 ملف ترحيل، والأسماء والإصدارات لا تتطابق واحدًا بواحد. لا تستخدم المجلد الحالي وحده لإعادة إنشاء قاعدة جديدة قبل توحيد التاريخ واختبار الاستعادة.
5. **بيانات المؤسسة الحالية:** توجد دفعات مورد غير مخصصة في الحساب التشغيلي. لا تعد تخصيصها أو حذفها أو تعديلها دون مطابقة إيصالات الدفع وسجل الحساب وموافقة مالك الحساب.
6. **التسليم التجاري:** جهّز سياسة الخصوصية وشروط الاستخدام وآلية الدعم والتسعير قبل قبول عملاء يدفعون.

## قواعد السلامة

- لا تحذف أو تعكس أو تعيد تخصيص أي حركة مالية لمجرد أن رصيدًا يبدو غير متوقع.
- استخدم دوال RPC المعتمدة بدل الكتابة المباشرة إلى جداول الأعمال.
- طبّق تغييرات قاعدة البيانات عبر ترحيل محفوظ في المستودع، ثم تحقق من الامتيازات والتقارير بعد التطبيق.
- لا تعتمد على نجاح البناء وحده؛ يجب أن تنجح اختبارات التطبيق وقاعدة البيانات أيضًا.
